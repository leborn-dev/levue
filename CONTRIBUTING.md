# Contributing to Leborn projects

Thanks for considering contributing! All Leborn projects share this guideline.

## Getting started

1. Read the project's `LEBORN.md` and `NOTICE` files to understand provenance.
2. Read the project's `README` and [development setup](.github/CONTRIBUTING.md#development-setup) for the pinned Node and pnpm versions.
3. Open an issue before starting significant work, so we can align on direction.

## Reporting issues

- Use GitHub Issues. Include reproduction steps, expected vs actual behavior, and environment details.
- For security issues, please do **not** open a public issue. See SECURITY.md (coming soon) or contact the Leborn team privately.

## Pull requests

- Fork the repository and create a feature branch.
- Keep PRs small and focused. One concern per PR.
- Include tests when reasonable.
- Reference the related issue in the PR description.
- Be patient: maintainers review when capacity allows.

## Code of Conduct

By contributing, you agree to abide by the [Code of Conduct](./CODE_OF_CONDUCT.md).

## Licensing

By submitting code, you agree that your contributions will be licensed under the same license as the project (see `LICENSE` and `NOTICE`).
